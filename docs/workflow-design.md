# 업무·관리 화면 디자인 적용

## 적용 범위

대시보드(`/dashboard`), 결재함(`/admin/approvals`), 기안·업무보고(`/drafting`), 조직관리(`/admin/organization`), 인사관리(`/admin/employees`), 급여관리(`/admin/salary`), 휴가신청(`/leave`), 지출결의 신청(`/expense`), 서류발급(`/documents`, 기존 `/official-letters` 별칭), 공지 게시판(`/board`), 지출결의 조회(`/admin/finance-stats`), 시스템 설정(`/admin/settings`), 구독 관리(`/subscription`)에 동일한 색상·SUIT 글꼴·레이아웃을 사용한다. `WorkspaceShell`은 이 경로의 회사 계정에만 `workflow-theme`을 적용한다. 플랫폼 운영 화면의 기존 표시·라우트 권한은 유지한다.

공통 색상은 `WorkflowTheme.css`의 사용자 지정 토큰을 기준으로 한다. 배경은 neutral-100, 카드는 흰색, 선택 배경은 primary-50, 선택 표시는 primary-500이다. 작은 흰색 버튼 글자의 가독성을 위해 주요 버튼 배경에는 primary-800을 사용한다. 키보드 포커스는 secondary-500을 사용한다. 패널 모서리는 12px, 입력·버튼은 8px이며 모바일 입력·버튼은 최소 44px 높이를 사용한다.

SUIT Variable 2.0.5는 `client/public/fonts/`에서 자체 제공하며 SIL Open Font License 원문을 함께 보관한다. 외부 폰트 요청이나 CSP 완화는 필요하지 않다. 기존 서버 PDF의 글꼴·양식·인감 실측 크기는 변경하지 않는다. 급여 명세서의 기존 인쇄 스타일은 유지하고 새 급여 화면 CSS는 `@media screen`에 한정한다.

## 화면과 기능

- 대시보드: 오늘 근태·최근 기록·연차 요약, 최근 30일 발급 서류와 기간 조회, 데스크톱 4열·모바일 2열 문서 카드, 월별 근태와 요약을 제공한다. 출퇴근 기록·직원별 조회·다운로드 API를 유지한다. 달력 첫 주의 공백은 실제 월 시작 요일로 정렬한다.
- 결재함: 휴가·지출·서류 탭과 실제 건수, 필터, 목록·상세 검토를 제공한다. 휴가·지출의 1차/최종 승인·반려·취소·복구와 첨부 증빙은 유지한다. 서류는 선택 시 기존 `get`으로 현재 개정을 읽고 서버가 반환한 `canReview`·`canFinalApprove`로만 승인 버튼을 표시한다. 기존 `review`에 개정·결정·반려 사유를 전달하며 관리자의 순서 건너뛰기는 허용하지 않는다. 고급 편집·번호·재배정·PDF·이력은 `상세 관리`에서 기존 화면으로 연결한다.
- 기안·업무보고: 목록과 편집 화면을 구분하고 데스크톱은 본문·결재선/첨부를 나란히, 모바일은 한 열로 배치한다. 기간 검색, 기안·일일·주간 구분, 조직 결재선, 저장/재시도, 미저장 이동 확인, 첨부, 보관본, 비밀번호 확인 삭제를 유지한다.
- 조직관리: 본부 목록과 팀·직원 영역, 본부장·팀장 지정, 직원 등록·권한·이동, 변경 이력을 같은 디자인으로 표시한다. 직원 ID 자동완성·기존 초기 비밀번호·최초 변경 조건은 유지한다.
- 인사관리: 직원 검색·본부/팀 필터, 직원 표·모바일 카드, 인사카드·연차·근태 상세, 계정 상태·초기화·삭제 기능을 유지한다. 상세 창은 화면 높이 안에서 내용을 스크롤한다.
- 급여관리: 기간·지급/공제/실수령 합계, 본부/팀·이름 필터, 데스크톱 급여 편집 표와 모바일 카드, 상세 명세서·승인 이력을 제공한다. 계산식·공제 가족 조건·세액표·저장·승인·이력 삭제 로직은 유지한다.
- 휴가신청: 연차 현황·신청서·신청 내역을 데스크톱에서 나란히, 좁은 화면에서는 한 열로 표시한다. 연차/반차 계산, 날짜·사유·증빙 입력, 본인 내역 조회와 기존 첨부 접근 조건을 유지한다.
- 지출결의 신청: 신청·수정 폼과 월별 본인 내역, 상태·금액 요약을 정리한다. 모바일 내역 카드와 상세 창에서 기존 첨부·수정·취소·삭제 동작을 제공하고 제출·업로드·상태 변경 로직은 유지한다.
- 서류발급: 공문·재직·경력 작성, 회사 템플릿과 종류/기간 검색, 모바일 문서 카드, 발급·재배정·이력·PDF·비밀번호 삭제를 제공한다. 회사 로고·인감 3MB 제한, mm 크기, 번호·위임·최종 승인과 미저장 변경 보호는 유지한다. 모바일 카드 스타일은 서류 목록 표에만 적용하며 증명서 미리보기의 표·인감 규격에는 적용하지 않는다.
- 공지 게시판: 실제 미확인/전체/분류별 건수, 검색·게시글 펼침, 기존 관리자 작성·수정·삭제 조건과 비공개 첨부를 유지한다. 서버의 회사·역할·작성자 권한은 확장하지 않으며 기존 규칙에 따라 부서관리자 자신의 글 수정과 회사 관리자 삭제를 검증한다. 작성 창은 작은 화면 안에서 스크롤한다.
- 지출결의 조회: 같은 회사에서 승인 완료된 내역의 기간·합계·건수를 표시하고 CSV·영수증 ZIP·인쇄 동작을 유지한다. 종료일 포함과 시작일 변경 시 한 달 뒤 종료일 계산도 유지한다. 작동하지 않던 장식용 검색·필터·상세 아이콘은 제거한다. 날짜 입력의 실제 터치 영역은 44px이며 인쇄 때는 화면용 헤더와 고정 높이·스크롤 제한을 해제하여 긴 보고서를 이어서 출력한다.
- 시스템 설정: 도메인·기존 직원 동기화, 관리자 비밀번호 변경, 회사 데이터 JSON 백업을 반응형 패널로 정리한다. 비밀번호 재인증·토큰 갱신·메일 확인·서버 동기화·로그아웃·회사별 백업 쿼리를 유지한다. 새 비밀번호 안내만 기존 실제 검증과 같은 12자로 바로잡는다.
- 구독 관리: 체험·정상·만료 상태와 기존 플랜·결제일·요금 표시, 고정된 PayPal 새 탭 링크와 결제 확인 요청을 유지한다. 동일 회사 ADMIN만 요청할 수 있고 중복 제출·실패 재시도·계정 변경 보호를 유지한다. 거래번호 제출은 이용 기간을 자동 활성화하지 않으며 기존 운영자 거래 확인 절차를 따른다.

## 격리와 검증 기준

인증 저장소, `ProtectedRoute`, 서비스 API, Cloud Functions, Firestore/Storage 보안규칙, 인덱스와 CSP는 변경하지 않는다. 회사·역할·본부 변경에 따른 기존 화면 재마운트를 유지하며, 공통 사이드바는 현재 회사 ID와 일치하는 회사명만 표시한다. 서류 상세의 지연 응답과 승인 후속 조회는 계정·회사·역할·조직·활성 세션·개정이 달라지면 반영하지 않는다.

모든 브라우저 데이터와 파일은 격리된 로컬 대역으로 검증하고 운영 회사 자료에는 쓰지 않는다. 최소 검증은 1440·1024·390·320px의 가로 넘침, 실제 자체 제공 SUIT 로딩, 모바일 메뉴의 Tab/Shift+Tab·Escape·포커스 복귀, 역할별 메뉴·권한, 기존 처리 흐름·다운로드·모달 접근이다. `container-type`은 편집/목록 영역에 두어 고정된 삭제·상세 창이 페이지 내부에 갇히지 않도록 한다.

서버 회귀 검사 930건(서류/기안/업무보고 125, 권한·회사 격리·비공개 Storage 743, 보안 API 53, 인증 상태 9), 클라이언트 단위 검사 19건, 관리자 UI 보안 회귀 18건이 통과했다. 관리자 UI 대역은 실제 오류 처리 도구를 불러오도록 보완하고 비밀번호 변경·세션 오류 때 새 업무 레이아웃도 표시하지 않는지 검증한다. 서버 줄 커버리지는 서류·기안 95.75%, 보안 API 97.48%이다. 기안·업무보고 29그룹, 최초 세 화면 통합 15그룹, 관리 세 화면 통합 10그룹의 브라우저 검증에서 런타임 오류·CSP 위반·외부 요청은 없었다. 배포 전 최종 빌드·타입·린트·브라우저 결과와 비밀값·diff 검사로 반영 대상을 확정한다.

휴가·지출 신청·서류발급·게시판 추가 적용에서도 위 자동 검사 967건을 다시 통과했다. 추가 네 화면의 1440·1024·390·320px 16개 조합과 실제 자체 제공 SUIT 로딩, 모바일 메뉴·신청/수정·첨부·문서 기간/종류 검색·템플릿 이미지/mm 규격·결재/PDF·비밀번호 삭제·게시글 역할·회사 전환을 브라우저 12그룹으로 검증했다. 기존 서류 별칭·기안 이동·모바일 하단 내역·상세 창·게시글 첨부는 추가 4그룹으로 확인했다. 480px 이하에서는 첨부파일명을 아이콘과 같은 독립 행에 배치하고 지출결의 상세 버튼은 자동으로 다음 행으로 이어지게 하여 한 글자씩 줄바꿈되지 않도록 한다. 실제 앱과 동일한 계정·회사·역할별 컴포넌트 키를 사용하고, 관리자 본인 서류의 자동 발급 및 기존 서버 삭제 권한을 재현한다. 결과는 실패·런타임 오류·CSP 위반·외부 요청 0건이며 모든 자료는 로컬 대역을 사용했다. 기존 서류의 이벤트·입력 검증·값·직인 스타일 계약 185개가 유지됨을 별도로 대조했다.

추가 관리 세 화면은 기존 967건에 PayPal 확인 요청 회귀 10건을 더해 자동 검사 977건이 통과했다. 결제 테스트 대역은 실제 역할 표시 함수를 불러오고 스타일 파일만 명시적으로 대체하도록 보완했다. 세 화면의 pre-render 로직과 이벤트·필수/활성 조건·값·결제 링크·React 키 계약을 원본과 대조했다. 브라우저 22그룹에서 1440·1024·390·320px, 짧은 320×480px, 날짜/합계/CSV/ZIP 원본과 계정 전환, 설정 재인증·백업, 구독 권한·멱등 확인 요청과 만료 경로가 통과했다. 83행 보고서는 인쇄 시 마지막 행까지 문서 흐름에 포함됨을 확인했다. 런타임 오류·CSP 위반·실제 외부 통신은 없었으며, 실제 결제나 운영 계정 메일 발송·비밀번호 변경은 수행하지 않았다.

웹은 GitHub `main` 푸시로 Cloudflare Pages에 배포하고, 해당 커밋의 배포 체크와 공개 JS·CSS·폰트의 실제 바이트를 대조한다. 백엔드 변경이 없으므로 Firebase 리소스 배포는 수행하지 않는다. 공통 입력·패널·상태 컴포넌트와 라우트별 코드 분할은 [공통 UI와 초기 로딩 개선](ui-components-loading.md)에 적용 내용과 측정 결과를 기록한다.

화면 분리 후에도 인증·세션에 필요한 Firebase 코어의 500kB 초과 빌드 경고는 남아 있다. 다음 성능 개선은 실제 사용자 환경의 측정을 기반으로 진행한다.
