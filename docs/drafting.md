# 기안서 작성·선택 결재

`/drafting`은 첨부 품의서 형식을 참고한 내부 기안서입니다. 사이드바의 **기안서작성**을 **지출결의 신청** 바로 위에 배치하고, `officialLetters`의 `DRAFTING` 유형으로 기존 서류 결재함·알림·대시보드·비공개 PDF 보관에 통합합니다.

## 작성과 결재

- 작성일은 한국 시간의 최초 저장일입니다. 기안자는 본부에 배정되어야 하며 팀장 단계를 선택하면 팀 배정도 필요합니다.
- 팀장·본부장은 계정 역할과 별도로 조직도의 `leaderId`·`headId`로 검증합니다. 대표는 해당 회사의 `adminUid`와 활성 회사 관리 권한을 확인합니다.
- 본부장 전결: 선택 팀장 → 선택 협조 본부장들 → 소속 본부장.
- 대표 결재: 선택 팀장 → 선택 소속 본부장 → 선택 협조 본부장들 → 대표.
- 협조 본부는 같은 회사의 다른 본부만 최대 5개 선택합니다. 겸직 UID는 가장 뒤의 책임 단계로 합치고 직책을 함께 기록합니다.
- 현재 차례의 지정 결재자만 승인·반려합니다. 관리자 작성자도 자동 승인되지 않으며, 일반 서류의 최종 승인 위임을 적용하지 않습니다.
- 기안자 또는 회사 관리자가 수정·재제출할 수 있습니다. 관리자 대리 제출 시 실제 제출자의 UID·이름·시각을 기록하고 PDF에도 대리 제출로 표시합니다. 발행본 수정은 회사 관리자만 수행합니다.

## 번호와 보관

- 회사 ID + 불변 본부 ID + 한국 연월(`YYYYMM`)의 카운터로 최초 저장 순번을 원자적으로 배정합니다.
- 표시 예: `전략기획 11-003`. 본부명 끝의 `본부`를 제외하며 월 두 자리와 최소 세 자리 순번을 사용합니다. 999 다음은 1000으로 이어집니다.
- 생성 시 기안일·본부명·작성자명과 번호를 고정합니다. 내용 개정, 결재선 변경, 최종 발행이나 삭제로 번호를 바꾸거나 되돌리지 않습니다.
- UUID 생성 요청은 작성자·회사별로 멱등 처리합니다. 같은 요청·같은 내용은 같은 기안 ID를 반환하고 다른 내용 또는 삭제된 요청은 거절합니다.
- `draftingCounters`와 `draftingRequests`는 서버 전용입니다. 클라이언트 읽기·쓰기 권한은 기존 catchall 거부 규칙을 유지합니다.

## PDF와 보안

- A4 상단에 기안일·번호·수신·참조·발신·기안자·보존년한을, 우측에 담당자와 실제 결재자 이름·직책·승인 일시를 표시합니다. 참조 요청사항과 긴 본문은 다중 페이지로 이어집니다.
- 보존년한 `3년`은 양식 표시이며 자동 삭제 정책이 아닙니다. 인감·로고 없이도 기안 결재와 PDF 발행이 가능합니다.
- PDF 경로는 문서 ID·개정·번호 해시로 서버에서 구성합니다. 승인된 현재 개정만 내려받으며 파일 반환 직전에 회사·계정·개정·승인 상태를 다시 확인합니다.
- 기존 서류의 회사 관리자 열람 범위는 유지합니다. 그 밖의 사용자는 본인 작성·지정 결재 문서만 접근하며, 일반 서류 승인 위임만으로 기안을 열람하거나 승인할 수 없습니다.
- 수정·재배정 시 기존 승인을 초기화하고 이력을 남깁니다. 보관 PDF 삭제는 같은 서버 계산 경로를 사용합니다. 발행본 삭제는 기존 관리자 비밀번호 재확인·잠금·재시도 절차를 사용하며 번호 카운터와 요청 예약은 유지합니다.

## 첨부자료

- 기안의 첨부자료에서 외부 견적서 등 PDF·PNG·JPEG·WebP·GIF 원본을 선택합니다. 파일당 10MB, 최대 5개, 합계 30MB까지 허용하며 SVG·HTML 등 실행 가능한 형식은 허용하지 않습니다.
- 선택한 파일은 기안 저장 시 비공개 서버 업로드 후 연결합니다. 회사·작성 요청 또는 기존 기안에 귀속된 서버 계산 경로를 사용하고 원본은 덮어쓰지 않습니다. 회사 ID나 객체 경로를 클라이언트가 지정해 다른 기안에 주입할 수 없습니다.
- 첨부 추가·제거는 내용 변경과 같은 새 개정으로 저장하여 기존 승인과 PDF를 초기화합니다. 기안자·지정 결재자와 해당 회사 관리자만 현재 첨부를 다운로드하며, 다른 본부의 일반 직원이나 지정되지 않은 부관리자는 접근할 수 없습니다.
- 수정 전 첨부 참조는 기존 내용과 함께 관리자 전용 이력에 보관합니다. 개별 이력 삭제 후에는 해당 이력으로 다운로드할 수 없으며, 공유 원본의 손실을 막기 위해 파일은 기안 전체 삭제까지 비공개 보관합니다. 기안 전체 삭제는 첨부 원본까지 기존 재시도 가능한 삭제 절차로 정리합니다.
- 기안 PDF에는 파일명·용량 목록을 표기하고 첨부 원본은 별도 다운로드합니다. 기존 텍스트 첨부 설명은 과거 내용 보존을 위해 읽기 전용으로 표시합니다.

## 검증

`npm run test:official-letters`는 기존 공문·증명서와 신규 기안서 테스트를 함께 실행합니다. 테스트에는 로컬 Firestore 에뮬레이터가 필요하며 운영 프로젝트 실행을 금지합니다. 번호 동시성·연월/본부 격리·요청 재시도·조직 책임자 변경·퇴사/정지·순차 결재·대리 제출·PDF 보관/삭제를 검증합니다.
